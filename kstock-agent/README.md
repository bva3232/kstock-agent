# kagent — DART 공시 + KRX 시세 기반 시장 브리핑 봇

기자의 취재 보조와 개인 투자 판단 보조를 겸하는 도구입니다.
**예측기가 아니라 자료 정리기**입니다. 이 구분이 이 프로젝트의 전부입니다.

---

## 1. 설치

```bash
pip install -r requirements.txt
cp config.example.yaml config.yaml
```

`config.yaml` 에 DART API 키를 넣습니다. 키는 https://opendart.fss.or.kr 에서 무료 발급되고,
발급 즉시 쓸 수 있습니다. (환경변수 `DART_API_KEY` 로도 됩니다.)

리포트를 텔레그램으로도 받고 싶다면 `config.yaml` 의 `telegram.bot_token`/`chat_id` 를 채우세요.
발급 방법은 [QUICKSTART.md](QUICKSTART.md#6-텔레그램-발송-설정-선택) 참고. 비워두면 발송 없이 콘솔 출력만 됩니다.

## 2. 실행 — 하루 2회 사이클

```bash
# ① 장 마감 후 (15:40) — 오늘 예측 채점 + 내일 예측 생성
python run_evening.py

# ② 개장 전 (07:30) — 밤사이 변동 반영해 예측 수정
python run_premarket.py
```

이 두 개가 프로세스 1과 2를 함께 처리합니다.

| 프로세스 | 마감 후 (15:40) | 개장 전 (07:30) |
|---|---|---|
| P1 단타 TOP5 | 전종목 스크리닝 → 내일 후보 5종목 예측 | 갭·공시 반영해 수정 |
| P2 핵심종목 | 000660 / 005930 예측 | 갭·공시 반영해 수정 |
| 채점 | 어제 예측을 오늘 종가로 채점 | — |

### 개별 도구

```bash
python run_reporter_radar.py --days 3           # 기자용 공시 레이더 (DART만)
python run_stock_analysis.py --ticker 000660    # 개별 종목 심층 분석
python run_backtest.py --days 400 --null-check 20   # 신호 검증
python run_morning_brief.py                     # HTML 브리핑 리포트
```

### 자동 실행

**PC가 꺼져 있어도 돌아가야 하면** 로컬 crontab 대신 클로드 클라우드 스케줄(`/schedule`)을 씁니다.
매일 07:30 `run_premarket.py`, 15:40 `run_evening.py` 를 클라우드에서 실행하도록 등록하면
사용자 PC 상태와 무관하게 실행되고, 끝나면 텔레그램으로 리포트가 옵니다.

직접 보유한 서버/PC를 상시 켜두고 쓰는 경우엔 기존 crontab 방식도 가능합니다.

```bash
crontab -e
40 15 * * 1-5 cd /path/to/kstock-agent && /usr/bin/python3 run_evening.py   >> logs/evening.log 2>&1
30  7 * * 1-5 cd /path/to/kstock-agent && /usr/bin/python3 run_premarket.py >> logs/premarket.log 2>&1
```

**기본은 국내 데이터(DART + KRX)만 사용합니다.** 미국장 연동은 `--use-us` 로 별도 활성화하며
`pip install yfinance` 가 필요합니다. 08:00~08:50 NXT 프리마켓 호가를 보고
`--gap 000660=-4.2` 로 직접 넣으면 국내 데이터만으로도 갭이 반영됩니다.

### 출력 형태

```
■ SK하이닉스 (000660)  전일종가 1,495,000원
   ▶ 하락 우세 — 상승 47% / 하락 53%

   ▲ 오르는 경우  보통 1,573,000원 (+5.2%)   상위10% 1,712,000원 (+14.5%)
   ▼ 빠지는 경우  보통 1,410,000원 (-5.7%)   하위10% 1,281,000원 (-14.3%)

   큰 변동 확률: ±3% 초과 58% · ±5% 초과 41% · ±10% 초과 17%
   기대값(참고): -0.85%, 1,482,300원 — 확률가중값이라 여기서 끝나는 날은 드뭅니다
   60% 구간: 1,396,000 ~ 1,594,000원 / 80% 구간: 1,336,000 ~ 1,653,000원
   지지 1,481,000원 / 저항 1,600,000원
   변동성: 일간 8.5% / ATR 9.2% → 권장 손절폭 -18.4%

┌────────────────────────────────────────────────────────────────
│ 한 줄 요약
│ ▼ SK하이닉스 — 하락 우세(53%) · 오르면 1,573,000원(+5.2%) /
│   빠지면 1,410,000원(-5.7%) · 5% 이상 움직일 확률 41%
└────────────────────────────────────────────────────────────────
```

### 왜 '예상 종가 하나'를 헤드라인에 쓰지 않는가

초기 버전은 `예상 종가 1,482,300원 (-0.85%)` 를 결론으로 냈습니다. 틀린 값은 아닙니다.
(상승 47% × +5.2%) + (하락 53% × -5.7%) = -0.85% 로 정확히 기대값입니다.

문제는 **실제로 -0.85% 로 끝나는 날이 거의 없다**는 것입니다. 하루 변동성 8.5% 짜리
종목에서 ±1% 안에 들어오는 날은 10% 남짓이고, 나머지 90%는 크게 오르거나 크게 빠집니다.
꼬리가 두꺼운 분포에서 평균은 가장 쓸모없는 요약값입니다.
그래서 헤드라인을 **오르면 얼마 / 빠지면 얼마** 두 갈래로 바꿨습니다.

이 형식이 실전에서도 바로 쓰입니다.

- 목표가 = 오르는 경우 '보통' 값 (+5.2% → 1,573,000원)
- 손절가 = 빠지는 경우 '보통' 값보다 아래 (-5.7% 이탈 시 이탈로 간주)
- 포지션 크기 = ±10% 초과 확률 17% 를 감안해 산정

'보통'은 중앙값, '상위10%/하위10%'는 90분위입니다. 평균을 쓰면 꼬리에 끌려 올라가
두 값이 붙어버려서 구분이 안 됩니다.

## 3. 구조

```
kagent/
├── dart.py        DART OpenAPI 클라이언트 (공시검색, 고유번호, 주요계정)
├── disclosure.py  공시 분류 엔진 + 기자용 이상징후 탐지
├── krx.py         KRX 데이터 (pykrx 래퍼, 날짜별 스냅샷 캐싱)
├── signals.py     추세·모멘텀·거래대금·변동성 지표
├── patterns.py    차트 구조 추출 + 셋업별 조건부 과거 통계
├── scenario.py    다음날 변동폭 실측 분포 + 분기 시나리오
├── forecast.py    방향 확률 + 예상 단가 + 구간 생성
├── overnight.py   간밤 미국장 수집 + 갭 연동 회귀
├── ledger.py      예측 원장 (기록·채점·캘리브레이션)   ← 시스템의 심장
├── screener.py    유니버스 필터 → 합성점수 → 포지션 사이징
├── backtest.py    신호 검증 (IC, 분위수익, 비용차감 기대값)
└── brief.py       HTML 리포트 렌더링
```

### 예측 원장이 왜 심장인가

`ledger.py` 는 모든 예측을 SQLite에 남기고 다음날 종가로 채점합니다.
세 가지를 봅니다.

- **방향 적중률** — 상승/하락을 맞췄나. z값이 2 미만이면 동전던지기입니다.
- **단가 오차(MAE)** — 예측 중심값과 실제 종가의 차이. 이게 실제 평균 변동폭보다
  크면 "그냥 전일 종가를 그대로 부르는 것"과 다를 게 없다는 뜻입니다.
- **구간 커버리지** — 80% 구간이라고 한 곳에 실제로 80%가 들어왔나.

셋 중 **커버리지가 가장 중요합니다.** 방향 적중률 55%는 운으로도 나오지만,
80% 구간에 실제로 80%가 들어오는지는 시스템이 자기 불확실성을 정직하게
표현하는지를 직접 보여줍니다. 커버리지가 60% 아래면 밴드가 좁은 것이고,
그 상태로 손절선을 잡으면 방향을 맞춰도 장중에 털립니다.

기록이 20건 미만이면 `verdict()` 는 아예 판단을 거부합니다.
50건쯤 쌓인 뒤에 실전 투입 여부를 결정하세요.

### 설계상 의도한 것들

**공시 분류는 LLM이 아니라 규칙 기반입니다.** `disclosure.py` 의 `RULES` 표를 보면
어떤 보고서명이 어떤 카테고리로, 어떤 방향과 가중치로 매핑되는지 전부 드러나 있습니다.
같은 입력이면 항상 같은 출력이 나오고, 기사에 쓸 때 "왜 이렇게 분류했나"를 설명할 수 있습니다.
LLM 요약을 쓰면 편하지만 재현되지 않고, 틀렸을 때 어디서 틀렸는지 추적이 안 됩니다.

**전종목 패널을 종목별이 아니라 날짜별로 수집합니다.** 종목별로 돌면 2,700회 요청이지만
날짜별 스냅샷을 받아 피벗하면 90회면 끝납니다. KRX 쪽 부하도 훨씬 적습니다.

**지표 파라미터를 일부러 적게 뒀습니다.** 파라미터가 많을수록 과거에 잘 맞는 조합을
찾기는 쉬워지지만, 그렇게 찾은 숫자는 미래에 재현되지 않습니다.

**포지션 사이징은 리스크 역산입니다.** "100만원을 4등분"이 아니라
"이 종목의 ATR 기준 손절선까지 갔을 때 손실이 계좌의 2%가 되는 수량"을 계산합니다.
변동성이 큰 종목일수록 자동으로 적게 잡힙니다.

## 4. 시드 100만원에서 현실적으로 생기는 문제

미리 알고 시작하는 편이 낫습니다.

- **거래비용이 수익률을 잠식합니다.** 증권거래세·농특세에 증권사 수수료까지 왕복
  0.2~0.4% 수준입니다. 5영업일 보유로 평균 0.3% 먹는 전략이면 비용 빼고 남는 게 없습니다.
  세율과 수수료는 계좌마다 다르니 본인 기준으로 `roundtrip_cost_pct` 를 고쳐 쓰세요.
- **고가주는 아예 못 삽니다.** 1주에 30만원 넘는 종목은 100만원 계좌에서 분산이 불가능합니다.
  리포트에서 `수량 0주` 로 표시됩니다.
- **분산이 사실상 안 됩니다.** 4종목으로 나누면 종목당 25만원인데, 이 정도면
  개별 종목 리스크가 그대로 계좌 리스크입니다.
- **표본이 너무 적습니다.** 100만원으로 20~30번 거래해봐야 실력인지 운인지 구분이 안 됩니다.
  이 금액대는 수익을 내는 계좌가 아니라 **시스템을 검증하는 계좌**로 보는 게 맞습니다.

그래서 이 도구의 초기 용도는 **모의 기록**을 권합니다. 매일 리포트를 뽑고, 실제로 샀다면
어떻게 됐을지 스프레드시트에 기록해서 3개월쯤 쌓아보세요. 그 기록이 백테스트보다 정직합니다.

## 5. 왜 '차트 해석'이 아니라 '조건부 실측'인가 — 2026년 8월 5~6일 사례

**8월 5일(수) 마감 시점**, SK하이닉스의 관측 가능한 신호가 전부 매수를 가리켰습니다.

| 항목 | 값 |
|---|---|
| 종가 | 1,668,000원 (+5.77%) |
| 외국인 순매수 | 6,595억원 (시장 순매수 1위) |
| 코스피 | 6,598.26 (+3.76%), 장초반 매수 사이드카 |
| ADR | +8.17% |
| 애널리스트 | 매수 38 / 매도 0, 목표주가 평균 316만원 |
| 헤드라인 | "7월 수급 충격 끝났다", "8월 반도체 실적 장세 본격화" |

차트도 완벽했습니다. 대량거래 장대양봉, 정배열, 신고가 흐름 복귀.
`screener.py` 를 그날 돌렸다면 SK하이닉스가 1위로 나왔을 겁니다.

**8월 6일(목)** — 코스피 6,296.38(-4.58%), 매도 사이드카 발동.
SK하이닉스는 장중 -10% 가까이 급락했습니다.
원인은 간밤 샌디스크의 부진한 실적 전망, **어제 차트 어디에도 없던 정보**였습니다.

그런데 예측 가능했던 것이 하나 있습니다. 5일자 기사에서 KB증권 연구원이 이미
"웨스턴디지털과 샌디스크 실적이 반도체주 상승 지속 여부를 가늠할 변수"라고 짚었습니다.
**방향은 몰라도 무엇이 방향을 결정할지는 알 수 있었다**는 뜻입니다.

그래서 `scenario.py` 는 점 예측 대신 이렇게 출력합니다.

```
[분기 시나리오]
  · 상방 시나리오: 1차 저항 돌파
      과거 20일 고점 돌파 249회 → 다음날 같은 방향 54%
      (아무 날이나 53%, 차이 +1.3%p, t=0.7)
  · 하방 시나리오: 1차 지지 이탈
      과거 20일 저점 이탈 105회 → 다음날 같은 방향 50%
      (아무 날이나 47%, 차이 +2.4%p, t=-0.2)

[차트에 없는 변수 — 이게 방향을 결정할 가능성이 높음]
  · 샌디스크/WD 실적 (현지시간 장마감 후)
```

"돌파하면 간다"는 통념이 실제로는 아무 날이나 오를 확률과 1.3%p 차이이고
t=0.7로 통계적 의미가 없다는 게 숫자로 드러납니다. `patterns.py` 의 셋업 12개도
대부분 `무의미` 판정이 나올 겁니다. 그게 고장이 아니라 정확한 결과입니다.
**시스템이 "모르겠다"고 말할 수 있어야 합니다.**

### 그러면 무엇이 예측 가능한가

1. **이벤트 캘린더** — 오늘 밤 무슨 실적·지표가 나오는지. 확정 정보입니다.
2. **변동폭** — 방향은 몰라도 크기는 예측됩니다. 변동성은 군집성이 강해서
   오늘 크게 움직였으면 내일도 크게 움직입니다. 손절폭 산정의 근거입니다.
3. **공시 이벤트** — 유상증자·자사주·횡령 같은 사건은 노이즈 대비 신호가 큽니다.
4. **쏠림의 되돌림** — 시총 상위 2종목 비중이 58.9%까지 갔다 되돌아오는 구조적 흐름.

`--event` 옵션으로 예정 이벤트를 넣으면 리포트에 함께 출력됩니다.
이벤트 캘린더 자동 수집은 다음 단계 작업입니다.

### 신호 검증

`run_backtest.py` 를 꼭 돌려보세요. t 통계량이 2 미만으로 나오면 그 신호는
쓰지 말아야 합니다. 이 숫자를 직접 확인하는 것과, 남이 "잘 된다"고 말해주는 걸
믿는 것 사이에는 큰 차이가 있습니다.

### 노이즈 하한선 확인

```bash
python run_backtest.py --days 400 --horizon 5 --null-check 20
```

같은 모양의 **순수 무작위 가격 데이터**로 똑같은 백테스트를 20번 돌려서,
"신호가 전혀 없어도 이 정도 IC는 우연히 나온다"는 기준선을 잡습니다.
개발 중 실측해보니 이 기준선의 표준편차가 IC 0.02 안팎이었습니다.
즉 실제 데이터에서 IC 0.015가 나왔다면 그건 신호가 아니라 운입니다.
p-value가 0.10을 넘으면 그 신호는 버리는 게 맞습니다.

백테스트는 기본적으로 `lag=1`, 즉 **신호를 만든 다음 영업일 종가에 진입**하는 것으로
계산합니다. 마감 후 계산한 신호로 그날 종가에 샀다고 치면 성과가 부풀려지는데,
이 한 칸 차이가 생각보다 큽니다.

## 6. 앱으로 확장할 때 먼저 확인할 것

자동매매 앱까지 가려는 계획이라면 기술보다 규제가 먼저 걸립니다.
아래는 확인이 필요한 항목 목록이고, 법률 자문이 아닙니다.
실제 판단은 금융감독원 문의나 변호사 검토를 거치세요.

**규제**
- 불특정 다수에게 유료로 투자조언을 제공하면 **유사투자자문업 신고** 대상이 될 수 있습니다.
- 이용자 자산을 대신 운용하면 **투자일임업**에 해당해 인가가 필요합니다.
  "앱이 알아서 매매"는 여기 걸릴 가능성이 높습니다.
- 알고리즘이 일임 판단을 하는 서비스는 **로보어드바이저 테스트베드** 통과가 요구되는 경우가 있습니다.
- 본인 계좌만 본인이 자동매매하는 것은 성격이 다릅니다. 배포 여부가 갈림길입니다.

**기자 신분에서 추가로 걸리는 부분**
- 본인이 기사를 쓰는 종목을 매매하면 이해상충 문제가 생깁니다. 소속사 윤리강령에
  보유종목 신고나 매매 제한 조항이 있는지 먼저 확인하세요.
- 취재 과정에서 얻은 미공개 정보로 매매하면 자본시장법 위반입니다.
  이 도구는 공개 데이터(DART 공시, KRX 시세)만 쓰도록 만들었는데, 이건 의도된 제약입니다.
- 기사 게재 전 해당 종목을 매매하는 선행매매도 문제가 됩니다.

**기술 로드맵 (규제 검토 후)**
1. 리포트를 3개월 이상 모의 기록 → 신호가 실제로 작동하는지 확인
2. 한국투자증권 KIS Open API 또는 키움 REST API **모의투자 계좌**로 자동 주문 연동
3. 모의투자에서 최소 3개월 검증 → 슬리피지·미체결·장애 상황 대응 확인
4. 그 다음에야 실계좌, 그것도 소액부터

## 7. 커스터마이징

가장 손댈 만한 곳:

- `disclosure.py` 의 `RULES` — 취재 분야에 맞는 공시 유형을 추가하세요.
  (예: 바이오 담당이면 임상시험 관련 자율공시 패턴)
- `screener.py` 의 `WEIGHTS` — 가중치를 바꾸면 성격이 달라집니다.
  단, 바꿀 때마다 백테스트를 다시 돌리세요. 안 그러면 그냥 취향에 맞춘 것뿐입니다.
- `config.yaml` 의 `universe` — 시총/거래대금 하한을 낮추면 종목수가 늘지만
  유동성 나쁜 종목이 섞여서 실제 체결이 안 되는 경우가 생깁니다.
